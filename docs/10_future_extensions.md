# 10. 将来拡張

## 1. GUI

CLIが安定してからGUIを検討する。候補は以下。

- PySide6
- DearPyGui
- Web UIではなくローカルGUI

GUIでは以下を優先する。

- 入力プレビュー
- line_maskプレビュー
- line_alpha_hrの部分拡大プレビュー
- プリセット切り替え
- パラメータ比較
- バッチキュー

## 2. CSP連携

直接プラグイン化は後回し。まずはCSPに読み込みやすい出力形式を整える。

- PNG 16bit
- TIFF
- レイヤー分離出力
  - tone_hr
  - line_alpha_hr
  - final
- PSD出力は将来検討

## 3. レイヤー分離出力

漫画作業では線と階調を別レイヤーで持てると便利だ。

```text
output_final.png
output_line_alpha.png
output_line_black.png
output_tone.png
```

## 4. 部分マスク編集

自動マスク抽出に失敗する箇所を手修正できるよう、外部ペイントソフトで編集したマスクを再入力できる機能を追加する。

```bash
mlu upscale input.png --line-mask edited_mask.png -o output.png
```

これにより、AIや閾値処理が苦手な葉・文字・複雑な窓枠を手動補正できる。

## 5. 局所プリセット

画像全体ではなく領域ごとにパラメータを変えたい場合がある。

- 建築線は硬く
- 木や葉は柔らかく
- 文字看板はPotrace
- 影は階調扱い

将来、領域マスクごとに処理設定を変える機能を検討する。

## 6. 自動パラメータ推定

教師あり学習なしで可能な範囲の自動推定を行う。

- 背景白率
- 線濃度分布
- line_mask面積率
- 入力のボケ量
- JPEGブロックノイズ量
- 純線画かグレー階調混在か

これらからプリセット候補を提案する。

## 7. 方向性線補正

建築線のガタつきをさらに抑えるため、線の局所方向を推定してSDFやマスクを補正する。

候補：

- structure tensor
- Hough line検出
- 線分近似
- 長直線だけ別処理

これは破綻リスクも高いためMVPには入れない。

## 8. thinning/skeletonベース補正

線の中心線を抽出し、幅を再付与する方式。線幅の一貫性には強いが、複雑な線や面ベタには弱い。

候補用途：

- 電線
- 柵
- 手すり
- 窓枠

MVP後に実験する。

## 9. GPU処理

Python側のSDF・合成はCPUで十分な可能性が高い。必要になった場合のみ以下を検討する。

- CuPy
- OpenCV CUDA
- Vulkan compute
- ONNX Runtime

VRAM 8GB制約があるため、GPU化よりも安定性を優先する。

## 10. 独自モデルなしのAI補助

教師あり学習は行わないが、既存ローカルモデルの追加対応は検討できる。

- OpenModelDB系のローカルモデル
- chaiNNer連携用エクスポート
- ONNXモデル呼び出し

ただし、モデルの商用利用可否と学習データ由来の問題は個別確認が必要だ。
