# 06. テスト・品質評価計画

## 1. 基本方針

高解像度の正解画像を使った教師あり学習は行わない。ただし、テスト用に合成図形をプログラムで生成し、既知の理想形と比較することは行う。これは学習ではなく、アルゴリズム品質の検証だ。

MVPでは白地黒線の純線画を対象にし、2x/3x/4x/6x/8xを検証する。速度より線の欠け、線幅保持、シャープさ、二値化耐性を優先する。

## 2. テスト画像カテゴリ

### 2.1 合成fixture

プログラムで生成する。

- 1px斜め線
- 2px斜め線
- 円弧
- 楕円
- 交差線
- 窓枠風の平行線
- パース線風の集中線
- 細い電線
- 点描ノイズ（除去寄りの挙動確認）
- 薄いグレー汚れ（白飛ばし確認）
- カケアミ風パターン（MVP品質保証外だが線集合としての観察用）

### 2.2 手元サンプル

ユーザーが自分で用意する。リポジトリには同梱しない。

- AI漫画背景化した街並み
- 室内背景
- 木・葉・自然物
- 建物外観
- 交通標識・看板
- 白地黒線の背景線画
- 細線が多い背景
- 文字看板や小さい閉領域を含む背景

### 2.3 破綻検出用

- ほぼ白紙
- ほぼ黒全面
- 低コントラスト
- JPEG圧縮が強い画像
- 透明PNG
- 16bit PNG
- 非常に細長い画像

透明PNGと16bit PNGはMVP必須品質ではなく、落ちないことと後続対応のための把握を目的にする。

## 3. 自動テスト

### 3.1 ユニットテスト

- グレースケール変換のレンジ確認
- 反転処理
- 閾値処理
- line_mask面積率
- SDF符号
- line_alpha_hrのサイズ
- 合成結果のレンジ
- 設定マージ
- 2x/3x/4x/6x/8xの出力サイズ
- 線幅補正の正負方向

### 3.2 スナップショットテスト

画像そのものを厳密比較すると環境差が出るため、以下の統計値で見る。

- 平均濃度
- 最小最大
- 線マスク面積率
- line_alphaの面積率
- connected component数
- skeleton長の概算

### 3.3 CLIスモークテスト

外部アップスケーラーなしで以下を確認する。

```bash
mlu upscale tests/fixtures/diagonal.png -o tmp/out.png --scale 4 --preset line_only --debug-dir tmp/debug
```

確認項目：

- 終了コード0
- 出力ファイル存在
- debugファイル存在
- run JSON存在
- 出力サイズが4倍

同じfixtureで `--scale 2`, `--scale 3`, `--scale 4`, `--scale 6`, `--scale 8` を確認する。

## 4. 画質指標

### 4.1 線幅保持

入力line_maskから距離変換で線幅を推定し、出力line_alphaから同様に推定する。

```text
expected_width_hr = source_width * scale + width_bias
```

許容範囲：MVPでは平均±10〜15%以内を目標にする。既定の `width_bias_source_px` は0とし、ユーザーが正負に調整できることも確認する。

### 4.2 連結性

細線が切れていないかを connected component 数で見る。

- 入力より極端にcomponent数が増える：線が切れている可能性
- 入力より極端にcomponent数が減る：線が潰れて結合している可能性

### 4.3 ジャギ指標

完全自動判定は難しいため、合成fixtureでのみ以下を見る。

- 斜め線のエッジ近傍で階段状の長い水平・垂直ランが増えない
- 円弧の輪郭が連続的なアルファ遷移を持つ
- ニアレスト拡大より高周波の格子成分が少ない

### 4.4 ハロー検出

線の外側に白浮き・灰色にじみが出ていないかを見る。

- line_alpha境界外の濃度変化
- tone_sourceの線除去跡
- 合成後の線周囲の局所コントラスト

## 5. 人間による確認手順

自動評価だけで漫画背景の品質は決めない。以下の見方を標準化する。

1. 100%表示
2. 200%表示
3. 印刷予定サイズ換算
4. CSPに貼り込んで600dpi原稿で確認
5. トーン化や二値化後も確認
6. 斜め線・曲線・窓枠・細線・文字看板を重点確認

## 6. デバッグレイヤー確認表

| レイヤー | 見る点 | 問題の例 | 調整パラメータ |
|---|---|---|---|
| `darkness` | 黒線が明るく出ているか | 線が薄すぎる | 入力補正、invert |
| `line_prob` | 線らしさが連続しているか | 影を拾いすぎる | adaptive, threshold |
| `line_mask` | 線の形が保たれるか | 細線が消える | weak threshold, cleanup |
| `tone_source` | MVP後: 線が消えているか | 二重線原因が残る | lift_strength, dilate |
| `tone_hr` | 階調が破綻していないか | 変な質感が出る | upscaler, noise |
| `line_alpha_hr` | 線が滑らかか | 太る・細る | width_bias, aa_radius |
| `final` | 実用品質か | 線が濃すぎる | line_darkness, gamma |

## 7. 性能テスト

### 7.1 目標

- 2000x1400 → 4000x2800 / 6000x4200 / 8000x5600を処理できる
- Python側処理でメモリが過剰に増えない
- 外部アップスケーラーのtile-size確認はMVP後

### 7.2 計測項目

- 入力サイズ
- 出力サイズ
- Python処理時間
- 最大RSSメモリ

### 7.3 目標値

速度はGPUやモデルで大きく変わるため、MVPでは固定値を置かない。ただし以下を目標にする。

- 失敗時に再試行可能な情報を出す
- 精度を落とさずに高速化できる処理だけ採用する

## 8. リグレッション防止

- `tests/fixtures` の合成画像は固定seedで生成する。
- 画像統計値の許容範囲をテストに入れる。
- 主要関数は入力レンジをassertする。
- バグ修正時は必ずfixtureを追加する。
