# 00. MVPスコープ決定

## 1. MVPの定義

MVPは、漫画背景用の白地黒線画像を高解像度な線画PNGへ変換し、実用判断できる最小版とする。

完成版の全機能ではなく、まず以下を安定させる。

- 白背景に黒線の線画画像を読む
- 必要に応じて `--invert` で反転素材を扱う
- 線らしい画素を抽出する
- SDFで2x/3x/4x/6x/8xの高解像度線に再レンダリングする
- 白キャンバス上に黒線として合成する
- 最終PNGを保存する

## 2. MVPで標準対応する入力

- 白地に黒線の漫画背景線画
- PNGを最優先
- JPEG/TIFFは読み込み対応候補だが、品質基準はPNGを中心に置く
- RGB/RGBA/Gray入力は受け付け、内部でグレースケール化する
- RGBA入力はMVPでは白背景に合成して処理し、最終出力はアルファなしPNGを既定とする
- 短辺1000px以上、長辺2000px前後を主な想定サイズとする

## 3. MVPで標準対応しない入力

- 黒ベタ背景に白線が乗る複雑な素材
- グレー階調やトーンを含む漫画背景
- ハッチング、カケアミ、点描、網点トーンを品質保証対象にすること
- 元写真そのもの
- カラー漫画背景

反転素材は `--invert` で白地黒線相当に変換して扱う。黒ベタ背景の複雑な素材は将来対応とする。

## 4. グレー画素の扱い

MVPでは階調を保存する目的では扱わない。

- 黒線として十分暗い画素は線として扱う
- 一定より薄いグレーは白へ飛ばす
- ハッチングやカケアミが入力に含まれる場合は線の集合として扱われる可能性があるが、MVP品質保証対象外とする
- 点描や網点トーンは原則として除去すべきノイズ寄りに扱う

## 5. 出力

MVPの主出力は最終PNG 1枚とする。

- 既定出力は8bitグレースケールPNG
- 16bit PNGは設計上の対応余地を残すが、MVP必須条件にはしない
- デバッグレイヤーは開発・調整用オプションとして保存できるようにする
- レイヤー分離出力、TIFF、PSDは将来対応とする

## 6. 品質方針

優先順位は以下とする。

1. 細い電線、柵、窓枠、建築線を欠けさせない
2. 線のジャギやガタつきを減らす
3. 元画像の線幅を忠実に保つ
4. 漫画原稿でのシャープさと二値化耐性を保つ
5. 処理結果を2x/3x/4x/6x/8xで保証する

細線保持とわずかな線太りが衝突する場合は、MVPでは線が欠けることをより避ける。ただし既定の線幅補正は0とし、ユーザーが正負に調整できるようにする。

## 7. 外部アップスケーラー

線画MVPではReal-CUGAN、waifu2x、Real-ESRGANなどの外部アップスケーラーを必須にしない。

理由は、MVP入力を純線画に絞るため、階調ブランチを拡大する必要がないからだ。外部アップスケーラー連携は、グレー階調やトーンを扱う将来フェーズで追加する。

## 8. バッチ処理

MVPでは単一画像処理を先に安定させる。

バッチ処理は、単一画像の品質と失敗時のデバッグが安定した後に追加する。速度より精度を優先し、精度を落とさずに高速化できる処理だけ採用する。

## 9. ライセンス方針

本体はApache-2.0を既定候補とする。

- 商用利用しやすい permissive license とする
- 外部バイナリ、外部モデル、GPL系ツールは同梱しない
- PotraceなどGPL系ツールを使う機能は任意の外部CLI連携として扱い、配布形態を分ける

## 10. リポジトリ方針

- 設定ディレクトリ名は既存の `config/` に統一する
- Python 3.11以上を対象にする
- 公開関数には型ヒントを書く
- 配列の値域と `0.0=黒, 1.0=白` の規約をdocstringに書く
- mypy導入はMVP必須にしない
